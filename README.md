# 器物有数 · 餐饮具贡献利润计算器

一个面向餐具、杯具、茶器等易碎商品商家的离线小工具。将售价、初次履约、渠道费用、广告和破损售后放到同一个订单口径里，计算**贡献利润**、保本售价与目标贡献利润率售价。

**项目状态：**2026-10-04 新建的 v1.0.0 开源版，使用 MIT 许可证。公开源码不代表已有用户、社区、维护历史、平台背书或任何开源优惠资格。

## 30 秒开始

1. 把 ZIP **完整解压**到一个文件夹，不要只把 HTML 拖出来
2. 双击文件夹中的 **index.html**，用现代浏览器打开
3. 把演示参数换成你的实际成本，右侧结果会自动更新
4. 改动参数后点击「保存当前方案」，最多保存 4 个快照；用「导出 CSV」留档

运行不需要安装 Node、Python、插件或网络。页面使用普通经典脚本，未采用容易触发本地 `file://` 模块跨域限制的 ES 模块。HTML、JS、CSS 必须保留在同一文件夹。如果打开的是编辑器，请右键 index.html → 选择浏览器。

如浏览器或企业策略不允许本地脚本，可在已安装 Python 的电脑上进入此文件夹执行 `python3 -m http.server 8000 --bind 127.0.0.1`，再打开 `http://127.0.0.1:8000`。这是可选本地预览，不是上线部署。

## 能做什么

- 每笔原始成交订单的贡献利润与贡献利润率
- 明确区分补寄、全额退款和手续费退回，防止初始成本重复计入
- 保本售价、目标贡献利润率售价、贡献保本广告费上限
- 指定月订单量的期望贡献利润
- 4 个方案快照与当前试算并排对比
- 价格 × 破损率敏感性矩阵
- 中文 UTF-8 CSV 导出，包含所有输入和关键输出
- 输入校验、边界状态提示、响应式页面和键盘可访问标签

## 隐私与数据保存

应用不使用网络请求、账号、云服务、跟踪、Cookie 或 localStorage；字体和脚本都不从外部加载。内容安全策略禁止网络连接。

## 先统一口径

所有金额使用人民币元，以**一笔原始成交订单**为单位。售价是买家支付的订单总额，包含向买家收取的运费；对应商品成本是整笔订单商品成本。不要混用“单件”与“整单”。

1. 初始商品、包装、出库运费、广告、固定手续费及其他每单成本，在所有原始订单中各计一次
2. 破损率分母是原始成交订单数；不要填“破损件数 / 件数”
3. 破损订单中，按「补寄占比」分为补寄与全额退款，二者互斥；每笔原始订单最多一次售后
4. 补寄成功且保留原始收入；只增加一次补寄所需成本
5. 全额退款收入归零，初次履约成本不恢复；额外退款处理成本只填新增费用，**不再填已退售价或初始商品成本**
6. 佣金和支付比例费均按原始售价计提。「手续费退回」对两者使用同一个退回比例；每单固定手续费永不退回
7. 费用含税 / 不含税口径要一致。工具不自动识别平台结算规则，请按实际规则折算

补寄商品/包装/运费与初次成本是**独立输入**。修改初次成本不会自动修改补寄成本，例如整套茶具中只补寄一个杯子时，可单独填这只杯子的成本。

## 计算公式

输入百分数都先除以 100，转为 0–1 的比例：

| 符号 | 含义 |
| --- | --- |
| P | 原始成交售价 |
| b | 破损率 |
| s | 破损订单中的补寄占比 |
| u = b × s | 每笔原始订单的补寄概率 |
| v = b × (1 − s) | 每笔原始订单的全额退款概率 |
| r | 佣金费率与支付费率之和 |
| q | 退款时比例手续费退回比例 |
| B | 初次商品 + 包装 + 出库运费 + 固定手续费 + 广告 + 其他每单成本 |
| K | 每次补寄的商品 + 包装 + 运费 + 其他成本 |
| H | 每笔退款额外处理成本 |
| C = B + uK + vH | 与售价无关的每单期望成本 |

- 预计保留收入：`R = P × (1 − v)`
- 预计比例手续费：`F = P × r × (1 − vq)`
- 贡献利润：`Π = R − F − C`
- 售价留存系数：`a = 1 − v − r(1 − vq)`，因此 `Π = aP − C`
- 贡献利润率：`Π / R`；`R = 0` 时无定义，不显示成 0%
- 破损带来的预计损失：`uK + vH + vP − Prvq`，即相对“没有破损”的贡献利润减少量；它**不是**在成本明细中再扣一次的附加项
- 月期望贡献利润：`月原始订单数 × Π`

### 保本售价与目标售价

- `a > 0` 时，保本售价为 `C / a`
- `a ≤ 0 且 C > 0` 时，提高售价不能实现保本，显示「不可达」
- `C = 0` 时售价 0 可以保本；若 `a < 0`，这只是售价为 0 的特殊点，涨价将亏损
- 目标贡献利润率为 `m`，且 `a − m(1 − v) > 0` 时，所需售价为 `C / [a − m(1 − v)]`
- 预计留存收入恒为 0 时，目标利润率无定义
- 零成本且任意正售价都能满足目标时，界面显示「¥0.01 起」，而不是把售价 0 的无定义利润率当成达标

UI 的保本与目标售价按分**向上取整**；广告费上限按分**向下取整**。其他展示金额四舍五入至分，内部计算不逐项取整。CSV 保留原始数学阈值及对应条件状态，便于复算；若状态为任意正售价达标，0 是数学下确界，实际按分报价从 ¥0.01 起。浮点计算在接近抵消的机器精度范围内做零值处理，因此不适合极端精度或审计场景。

贡献保本广告费上限为 `当前贡献利润 + 当前广告费`。如果它小于 0，则即使不投广告仍亏损。这个上限只保证贡献保本，不保证达到目标利润率，更不保证覆盖未录入固定经营成本。

### 假设示例：¥99 的餐饮具订单

**以下只是计算演示，不代表任何平台或行业的实际水平。**

售价 99，商品 32，包装 5，初次运费 8，广告 12；佣金 5%、支付 0.6%；破损率 3%，其中 80% 补寄；每次补寄商品 32、包装 5、运费 8；退款时比例手续费完全不退；其余费用为 0。

- 每 100 单：预计 2.4 单补寄、0.6 单全额退款
- 初始成本 B：57 元
- 预计补寄成本：0.024 × 45 = 1.08 元
- 预计全额退款收入损失：0.006 × 99 = 0.594 元
- 预计保留收入：98.406 元
- 比例手续费：5.544 元
- 每单贡献利润：98.406 − 5.544 − 57 − 1.08 = **34.782 元**，界面为 **¥34.78**
- 贡献利润率：约 **35.35%**
- 保本售价：约 61.9189765 元，界面为 **¥61.92**
- 目标贡献利润率 20%：约 78.5714286 元，界面为 **¥78.58**
- 1,000 单期望贡献利润：**¥34,782.00**

## 使用边界

这是**贡献利润工具，不是会计净利润、税务申报、平台结算对账或财务建议**。未录入的税费、固定人工、房租、折旧等不在结果内。

当前版本不支持部分退款、非破损退货、订单取消、退货残值、重复破损、多次补寄、保险赔付、平台补贴、优惠券承担拆分、佣金与支付费不同退款规则、阶梯费率、跨币种、采购数量折扣或库存现金流。若实际业务依赖这些规则，请勿直接把结果当作最终利润。

概率是长期平均值；实际单月会波动，工具不提供置信区间。敏感性矩阵是“其他参数不变”的情景，不是销售量或获客成本预测。

输入金额范围为 0–100,000,000，百分数为 0–100%，订单量为 0–100,000,000 的整数。合计费率可以达到或超过 100%，用于揭示异常假设，而不是静默改小。

## 开发与测试

**运行应用零依赖。**自动模型测试需要 Node.js 18 或更新版本：

```sh
node --test tests/*.test.cjs
# 或：npm test
```

`model.js` 可独立 `require('./model.js')`，公开 `defaults`、`fields`、`validate(input)` 和 `calculate(input)`。输入必须包含全部字段且为数字，不做字符串转换或缺失字段补齐；无效输入会抛出带 `errors` 字段的 ValidationError。

可选真实浏览器测试脚本 `tests/browser-smoke.py` 需要开发环境已有 Python Playwright 和 Chromium：

```sh
python3 tests/browser-smoke.py --chromium /path/to/chromium
```

浏览器测试是开发依赖，不是用户运行应用所需依赖。实际验证状态见 TESTING.md；不要把存在测试脚本误认为该浏览器套件已执行通过。
